# E-commerce Operations Analysis Agent

一個 3 天可完成的作品集 MVP，模擬電商營運分析師每天的流程：追蹤業績、預測明日需求、監控產能、分析優惠券，並回答資料有依據的營運問題。

## 對應職缺

| 職缺需求 | 本專案功能 |
| --- | --- |
| 自動化報表、業績預測、產能監控 | Dashboard、14 日趨勢、7 日移動平均、產能缺口警示 |
| 促銷與優惠券分析 | 使用率、AOV、折扣成本、營收歸因 ROI |
| AI chatbot 建置與優化 | 問答先讀取已計算 KPI，再輸出有資料依據的回覆 |
| End-to-end 商業分析 | 原始 CSV → KPI → 洞察規則 → 建議 → 可視化 |

## 快速啟動

不需安裝套件。需要 Python 3.10+：

```powershell
python app.py
```

開啟 http://127.0.0.1:8080。程式每次啟動會產生固定的 90 天模擬營運資料於 `data/daily_operations.csv`。

## 你能清楚解釋的核心邏輯

1. **預測**：明日需求 = 最近 7 天每日訂單的平均值。它是可解釋的基準模型；後續可與 Prophet／XGBoost 比較。
2. **產能**：產能利用率 = 今日訂單 ÷ 日處理上限；預測需求高於產能時，Agent 產生警示。
3. **促銷**：使用率 = 使用該券訂單 ÷ 全部訂單；AOV = 該券營收 ÷ 該券訂單。
4. **ROI 限制**：目前是營收歸因 ROI，不證明優惠券「造成」額外營收。要驗證增量效果，需設計 A/B test 或建立對照組。
5. **AI 安全性**：問答層不讓模型憑空計算；後端先算數字，回答只能引用這些已計算的值。

## 三天完成規劃

### Day 1 — 資料與報表

- 跑起 Dashboard，理解 CSV 每個欄位與 KPI 公式。
- 將 `make_demo_data()` 的資料情境調整成你能說明的商業故事。
- 練習解釋「營收 = 訂單數 × AOV」及這兩者如何拆解。

### Day 2 — 預測、產能、促銷洞察

- 解釋 7 日移動平均、產能缺口與警示門檻。
- 確認 SAVE50 與 FREE100 的使用率、AOV、折扣成本。
- 加入一個你自己的規則，例如：折扣成本占營收超過 15% 時提醒檢查門檻。

### Day 3 — Q&A、測試與面試說法

- 測試三種問法：營收、產能、優惠券。
- 準備簡報截圖與 2 分鐘 demo。
- 說明限制與下一步：串接真實資料庫、加入季節性／節慶特徵、A/B test、記錄 chatbot 無法回答的問題並補充知識庫。

## 面試 45 秒介紹

> 我做了一個電商營運分析 Agent，將每日彙總資料自動轉成 KPI、需求預測、產能風險與優惠券洞察。需求預測先採用可解釋的 7 日移動平均；當預測訂單高於日產能，系統會提出排班或備貨警示。促銷方面則追蹤使用率、客單價與折扣成本。Q&A 的設計是先由程式計算並取回數據，再生成回答，降低 AI 編造數字的風險。下一步會以 A/B test 驗證優惠券的增量效果。

## 資料說明

所有資料皆為程式生成的示範資料，不代表真實公司業績。請勿將此 MVP 的營收歸因 ROI 說成因果或增量 ROI。
